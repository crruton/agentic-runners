# Proposal

## Why

Агентная разработка забивает 21 раннер. Размер раннеров — слабый рычаг (E03). Нагрузку создают повторные прогоны неизменных тестов и холодный старт каждого xdist-воркера с отдельной копией импортов (0,8–1,5 GiB на воркер, OOM в cgroup). Решение должно работать без правок в репозиториях проектов (ADR-0002, ADR-0005).

## What Changes

- pytest-плагин `agentic_runtime`, подключаемый снаружи проекта (`-p agentic_runtime`).
- `--rt-workers N`: параллельный прогон форком от прогретого процесса с `gc.freeze()`, раскладка по файлам, перезапуск упавшего воркера форком, совместимость с `PYTEST_XDIST_WORKER`.
- `--rt-cache DIR`: локальный кэш результатов по хэшу входов файла теста.
- `--rt-telemetry`: строки `job-resources:` (cgroup v2, vmstat, PSI) в конце сессии.
- E04: проверка на синтетическом наборе тестов в Linux-контейнере с лимитами cgroup — память, время, OOM, доля пропусков по кэшу.

## Capabilities

### New Capabilities
- `test-runtime`: выполнение тестов проекта с общей памятью воркеров, кэшем результатов и телеметрией задания.

### Modified Capabilities
- нет

## Impact

- Код: `runtime/agentic_runtime/`, тесты плагина, демо-набор `runtime/demo/`.
- Зависимости: только pytest. xdist не нужен.
- Внедрение на раннерах — через `PYTEST_ADDOPTS` и `pre_build_script` в `config.toml`, когда появятся права (отдельный шаг).
