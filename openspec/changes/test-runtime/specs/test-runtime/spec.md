# Spec Delta

## Purpose

Выполняет тесты проекта дешевле по памяти и времени без изменений в его репозитории: воркеры с общей памятью, кэш результатов по входам и телеметрия ресурсов задания.

## ADDED Requirements

### Requirement: Параллельный прогон форком
С `--rt-workers N` (N > 1, Linux) плагин SHALL выполнять тесты в N процессах, созданных `fork()` после сбора тестов и `gc.freeze()`, с раскладкой по файлам. Итоговые результаты, коды выхода и JUnit MUST совпадать с последовательным прогоном.

#### Scenario: Те же результаты
- **WHEN** набор с проходящими, падающими и пропущенными тестами запускается с `--rt-workers 4` и без него
- **THEN** число passed, failed и skipped совпадает, код выхода одинаков

#### Scenario: Совместимость с фикстурами xdist
- **WHEN** фикстура читает `PYTEST_XDIST_WORKER`
- **THEN** в каждом воркере это `gw0` … `gwN-1`

### Requirement: Перезапуск упавшего воркера
Если воркер умер по сигналу, плагин MUST записать ошибку для теста, на котором он умер, и выполнить оставшиеся тесты этого воркера в новом форке, не более `--rt-max-restarts` раз.

#### Scenario: Воркер убит
- **WHEN** тест убивает свой процесс сигналом 9
- **THEN** этот тест помечен ошибкой «worker died», остальные тесты файла выполнены

### Requirement: Кэш результатов
С `--rt-cache DIR` плагин SHALL пропускать файлы тестов, у которых ключ входов совпадает с ключом последнего полностью успешного прогона, и сообщать число пропущенных тестов. Изменение файла теста, локального модуля из его замыкания импортов, conftest или lock-файла MUST менять ключ.

#### Scenario: Изменился импортируемый модуль
- **WHEN** после успешного прогона изменён модуль, который импортирует только `test_a.py`
- **THEN** при повторном прогоне выполняются тесты `test_a.py`, а остальные файлы пропускаются по кэшу

#### Scenario: Падение не кэшируется
- **WHEN** в файле упал хотя бы один тест
- **THEN** при следующем прогоне файл выполняется целиком

### Requirement: Остановка на первой ошибке
С `--rt-fail-fast` плагин SHALL останавливать сессию на первом упавшем тесте, в режиме форка — вместе со всеми воркерами. С `--rt-cache` тесты, упавшие в прошлых прогонах, MUST выполняться первыми; падение, не выполненное из-за остановки, MUST оставаться в списке.

#### Scenario: Повторный прогон после падения
- **WHEN** в прошлом прогоне упал тест в последнем файле
- **THEN** в следующем прогоне он выполняется первым, и сессия останавливается до остальных тестов

### Requirement: Ключ кэша по выполненному коду
С `--rt-select=coverage` плагин SHALL строить ключ файла тестов из замыкания импортов самого файла, содержимого его conftest-цепочки, файлов, выполнявшихся в его тестах в прошлом полностью успешном прогоне, и файлов, выполнявшихся на этапе setup фикстур в любом тесте. Карта MUST записываться только для файлов, прошедших целиком и без падений.

#### Scenario: Корневой conftest импортирует весь проект
- **WHEN** изменён модуль, который выполнялся только в тестах одного файла
- **THEN** при повторном прогоне выполняется только этот файл

#### Scenario: Код сессионной фикстуры
- **WHEN** изменён модуль, вызываемый сессионной фикстурой
- **THEN** выполняются все файлы тестов, использующие сессию

### Requirement: Телеметрия задания
С `--rt-telemetry` плагин SHALL печатать в конце сессии строки `job-resources:` в формате, который разбирает `runners/resources.py`.

#### Scenario: Разбор строк
- **WHEN** вывод сессии с `--rt-telemetry` подан в `runners.resources.parse`
- **THEN** поле `parsed` равно 1
