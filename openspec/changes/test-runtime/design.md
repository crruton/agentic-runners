# Design

## Decisions

1. **Свой цикл вместо xdist.** Хук `pytest_runtestloop`: родитель собирает тесты (импорты выполнены один раз), раскладывает файлы по воркерам жадно по числу тестов, делает `gc.collect(); gc.freeze()` и `fork()`. Ребёнок выполняет свои тесты через `pytest_runtest_protocol`, отправляет отчёты по pipe в сериализованном виде (`pytest_report_to_serializable`). Родитель восстанавливает их и вызывает `pytest_runtest_logreport`, поэтому терминал, JUnit и коды выхода работают штатно.
2. **Перезапуск воркера.** Перед каждым тестом ребёнок шлёт «старт nodeid». Если ребёнок умер по сигналу, родитель выдаёт для текущего теста ошибку «worker died (signal N)» и форкает нового ребёнка на оставшиеся тесты; число перезапусков ограничено `--rt-max-restarts` (по умолчанию 2).
3. **Совместимость.** В ребёнке выставляются `PYTEST_XDIST_WORKER=gwN` и `PYTEST_XDIST_WORKER_COUNT`, поэтому фикстуры «БД на воркер» работают без изменений. Терминальный вывод прогресса в ребёнке отключён, печатает только родитель.
4. **Ключ кэша.** sha256 от: содержимого файла теста; файлов локального замыкания импортов (AST, только файлы внутри rootdir); всех `conftest.py` по пути к файлу; lock-файлов (`uv.lock`, `poetry.lock`, `requirements*.txt`, `pyproject.toml`, `setup.cfg`); версии Python и плагина; дополнительных glob из `--rt-cache-extra`. Файл пропускается целиком, только если в прошлый раз все его тесты прошли.
5. **Телеметрия.** Тот же формат строк, что у santinel, чтобы `runners snapshot --only job_resources` разбирал логи любого проекта.

## Risks / Trade-offs

- Кэш не видит динамические импорты и внешнее состояние — смягчается `--rt-cache-extra`, отключением и правилом «кэш для проверки перед слиянием наполняет только CI».
- Фикстуры с потоками или открытыми сокетами до форка могут вести себя иначе — сессионные фикстуры создаются после форка, в каждом ребёнке.
- Только Linux для форка.
