# Design

## Decisions

1. **Хост — родительская cgroup.** `/emuhost` с `cpuset.cpus`, `memory.max`, `memory.swap.max` создаётся привилегированным контейнером `alpine` в корне cgroup v2 VM. Задания и сервисы запускаются с `--cgroup-parent=/emuhost`, поэтому лимиты хоста действуют на всех сразу, как на ноутбуке.
2. **Задание как в Docker executor.** Контейнер с `--cpuset-cpus` и `--memory = --memory-swap`. Postgres-сервис — отдельный контейнер без лимита задания.
3. **Нагрузка детерминирована.** Seed на шард; второй пайплайн получает свои seed. Упавший шард один раз перезапускается в конце очереди: так агент пушит снова.
4. **Калибровка без подгонки.** Пики воркеров — весь диапазон замеров santinel «largest reaped» (844–1473 MiB); рост памяти — к 40% прогона; число воркеров — по формуле `scripts/ci_shards.py`.
5. **Счётчики хоста.** `memory.events.local` (только сам хост) отдельно от иерархического `memory.events`; PSI cpu/memory/io хоста как доля времени прогона.

## Risks / Trade-offs

- Время масштабировано: сравниваются сценарии между собой.
- Фоновые контейнеры владельца в той же VM (стек aieval, около 20% одного ядра) добавляют шум.
- Не эмулируются диск, сеть, pull образов, класс 12 ядер / 31 GiB (VM даёт 19 GiB), сервер `buran`.
