# Design

## Context

- Есть: `collect/ci_history.py` (GitLab API → CSV), `collect/baseline.py` (CSV → markdown), `collect/ci_analytics.py` (БД → markdown), `collect/snapshot.py` (БД → jsonl.gz). Снимок от 09.11 лежит в `data/ci_analytics/20261109/`, выгрузка GitLab в `data/jobs_30d.csv`.
- БД доступна только под VPN, соединение рвётся. GitLab доступен без VPN.
- В компании все запуски CI идут через агентов. Поэтому доля агентов = 100%, и ключевой показатель агентской нагрузки — не «агент против человека», а пайплайны и задания на одну единицу работы (ветку или MR).
- В окружении есть pandas, psycopg2, requests, pytest. matplotlib нет.

## Goals / Non-Goals

Goals: одна команда снимает данные, одна команда строит отчёт; отчёт — материал для слайдов и точка «до» для экспериментов.

Non-Goals: PSI и cgroup (нужен Prometheus), сравнение экспериментов, веб-сервер, дашборд с live-данными.

## Образ результата

```
python -m runners snapshot            # один раз под VPN: БД + GitLab → data/snapshots/20261109/
python -m runners report              # офлайн, сколько угодно раз → out/report.html, out/metrics.json
```

`out/report.html` — одна страница, открывается двойным кликом. Сверху строка KPI (заданий в неделю и рост, часы раннеров и рост, p95/p99 очереди, доля отменённых до старта, доля главного проекта). Ниже девять разделов с SVG-графиками и таблицами, у каждой цифры подпись «источник · период». Графики можно скопировать в слайды как SVG.

## Decisions

1. **Пакет `runners/`, вход `python -m runners`.** Модули: `cli` (argparse), `snapshot` (обе выгрузки), `load` (снимок → DataFrame), `metrics` (чистые функции DataFrame → числа), `charts` (SVG), `report` (HTML и JSON). Метрики отделены от отрисовки, поэтому их можно тестировать без HTML.
2. **Графики — свой минимальный SVG** (вертикальные и горизонтальные столбцы). Новая зависимость ради трёх типов графиков не нужна, а инлайн-SVG даёт офлайн и тёмную тему через CSS-переменные.
3. **Формат снимка — jsonl.gz по таблице.** JSONB из `job_details` сохраняется как есть, файлы маленькие (около 4 МБ). Запись идёт во временный файл `*.part` и переименовывается после успеха (требование об обрыве сети).
4. **GitLab-выгрузка переиспользует `collect/ci_history.py`** как библиотеку. Сжатый CSV пишется без колонок `user` и `commit_title`: вместо логина хранится стабильный хэш автора (sha256 с солью из снимка). Это нужно для доли «главного автора» без ПДн.
5. **Классы заданий** — регулярки из `collect/baseline.py`, перенесённые в `metrics`. `collect/baseline.py` остаётся рабочим для старого CSV.
6. **Детерминизм `metrics.json`**: сортировка ключей, фиксированное округление, период берётся из данных, а не из текущей даты.
7. **Перенос старого снимка**: одноразовая подкоманда `runners import-legacy` раскладывает `data/ci_analytics/20261109/` и `data/jobs_30d.csv` в новую структуру (с хэшированием авторов).

## Risks / Trade-offs

- Свой SVG проще библиотек: нет интерактивности, подсказки только через `<title>`. Для слайдов этого хватает.
- Регулярки классов эвристичны, около 11% времени попадает в `other`. Раздел «Качество данных» показывает эту долю.
- У GitLab-выгрузки охват меньше (только проекты с членством владельца токена). Отчёт явно показывает расхождение с `ci_analytics`.
