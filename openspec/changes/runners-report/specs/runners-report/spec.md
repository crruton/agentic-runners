# Spec Delta

## Purpose

Строит воспроизводимый отчёт о нагрузке на CI-раннеры по локальному снимку: HTML для людей и доклада, JSON с показателями для сравнения «до/после» в экспериментах.

## ADDED Requirements

### Requirement: Отчёт строится офлайн из снимка
Команда `runners report` SHALL строить отчёт только из файлов снимка, без сетевых запросов. По умолчанию берётся последний снимок в `data/snapshots/`, явный выбор `--snapshot <YYYYMMDD>`.

#### Scenario: Сеть недоступна
- **WHEN** VPN выключен и снимок существует
- **THEN** `runners report` завершается с кодом 0 и создаёт `out/report.html` и `out/metrics.json`

#### Scenario: Снимка нет
- **WHEN** в `data/snapshots/` нет ни одного снимка
- **THEN** команда завершается с ненулевым кодом и сообщением, что сначала нужен `runners snapshot`

### Requirement: Самодостаточный HTML
`report.html` MUST быть одним файлом без внешних ресурсов (скриптов, стилей, шрифтов, картинок по сети), с графиками в инлайн-SVG, и MUST читаться в светлой и тёмной теме.

#### Scenario: Открытие без сети
- **WHEN** файл открыт в браузере без сети
- **THEN** все графики и таблицы отображаются, в HTML нет ссылок `http(s)://` на ресурсы

### Requirement: Разделы отчёта
Отчёт SHALL содержать разделы: ключевые показатели, тренд по неделям, очередь по часам и дням, отменённые до старта задания, классы заданий, топ проектов, разбор проекта с наибольшими часами раннеров, раннеры, качество данных.

#### Scenario: Все разделы на месте
- **WHEN** отчёт построен по снимку с обоими источниками
- **THEN** в HTML есть все девять разделов с заголовками и непустым содержимым

#### Scenario: Один источник
- **WHEN** в снимке нет `gitlab_jobs.csv.gz`
- **THEN** разделы, которым нужен GitLab, помечены «нет данных в снимке», остальные построены

### Requirement: Происхождение каждой цифры
Каждый показатель в отчёте MUST быть подписан источником (`gitlab` или `ci_analytics`) и периодом данных. Раздел «Качество данных» MUST показывать охват источников и их расхождения.

#### Scenario: Подпись показателя
- **WHEN** в отчёте показан p95 очереди
- **THEN** рядом указан источник и период, за который он посчитан

### Requirement: Машинно-читаемые показатели
`metrics.json` SHALL содержать все ключевые показатели отчёта с идентификатором, значением, единицей, источником и периодом. Повторный запуск на том же снимке MUST давать идентичный `metrics.json`.

#### Scenario: Воспроизводимость
- **WHEN** `runners report` запущен дважды на одном снимке
- **THEN** оба `metrics.json` побайтно совпадают

### Requirement: Без персональных данных
Отчёт и `metrics.json` MUST NOT содержать логины, имена и e-mail авторов запусков, а также заголовки коммитов.

#### Scenario: Проверка на логины
- **WHEN** отчёт построен по снимку, где у заданий есть авторы
- **THEN** ни одного логина автора нет в `report.html` и `metrics.json`

### Requirement: Оценка политик без изменений в репозиториях
Отчёт SHALL содержать раздел «Что если» с оценкой политики `interruptible` прямым replay истории из снимка (вариант на всех заданиях, без заданий выкатки, без веток main/master) и модельной очередью на откалиброванном числе слотов. Оценка MUST NOT требовать изменений в репозиториях или на раннерах.

#### Scenario: Устаревший пайплайн
- **WHEN** на той же ветке создан новый пайплайн, пока задание старого ещё работает
- **THEN** время от создания нового пайплайна до конца задания засчитывается как освобождённое, если задание не относится к выкатке

#### Scenario: Калибровка модели
- **WHEN** модель очереди строится по снимку
- **THEN** число слотов — наименьшее, при котором p95 модели без изменений не выше фактического p95, и оно указано в отчёте

### Requirement: Рост за окно и размер парка
Показатели роста SHALL считаться за последние 2 месяца по полным неделям, края окна — среднее за 2 недели. Размер парка во времени SHALL браться из `docs/research/fleet.csv` с источником каждой точки; источник `владелец` допустим и MUST быть виден в подписи показателя.

#### Scenario: Факт со слов владельца
- **WHEN** в `fleet.csv` точка с источником `владелец`
- **THEN** показатель роста парка подписан источником, включающим `владелец`
