# Proposal

## Why

Данные о нагрузке на раннеры лежат в двух местах: GitLab API и БД `ci_analytics`. Доступ к БД есть только через VPN, а соединение нестабильно. Сейчас цифры для доклада собираются разовыми запросами и вручную переносятся в markdown. Так их нельзя воспроизвести, а значит, нельзя честно сравнить «до» и «после» для экспериментов E01+ (ADR-0001).

Нужен один запускаемый артефакт: данные снимаются один раз, а отчёт строится из снимка офлайн и сколько угодно раз.

## What Changes

- Python-пакет `runners` с CLI `python -m runners`.
- `runners snapshot`: за один заход под VPN снимает БД `ci_analytics` целиком и историю заданий GitLab в `data/snapshots/<YYYYMMDD>/` с `manifest.json`. После этого сеть не нужна.
- `runners report`: из снимка строит самодостаточный `out/report.html` (один файл, без сети, графики в SVG, светлая и тёмная тема). Каждая цифра подписана источником и периодом.
- Разделы отчёта: ключевые показатели, тренд по неделям, хвост очереди по часам и дням, отменённые до старта задания, классы заданий, топ проектов, разбор главного проекта (santinel), раннеры, качество данных.
- Каждый показатель отчёта дублируется в `out/metrics.json`. Это машинно-читаемая база для сравнения «до/после» в следующих изменениях.
- Существующий снимок от 09.11 переносится в новую структуру. `collect/snapshot.py` поглощается пакетом.

Вне рамок: сбор PSI и cgroup (нужен `GRAFANA_TOKEN`, отдельное изменение), команда `runners compare` для экспериментов (следующее изменение, опирается на `metrics.json`), любые изменения на раннерах.

## Capabilities

### New Capabilities
- `ci-snapshot`: разовый офлайн-снимок источников данных CI с манифестом.
- `runners-report`: воспроизводимый отчёт о нагрузке на раннеры по снимку (HTML и JSON).

### Modified Capabilities
- нет

## Impact

- Новый код: `runners/` (пакет), `tests/`.
- `collect/ci_history.py` используется как библиотека (без изменения поведения). `collect/snapshot.py` удаляется, его логика переходит в `runners/snapshot.py`.
- Зависимости: pandas, psycopg2, requests (уже используются). Новых нет.
- Данные: `data/snapshots/` в `.gitignore` (уже покрыто `data/`), `out/` добавить в `.gitignore`.
