# Design

## Decisions

1. **Логи читаются кусками.** Два Range-запроса (первые и последние 24 КБ): строки `workers:`/`Running on CPU` в начале, `job-resources:` в конце. Если сервер отдал 200, второй запрос не делается.
2. **Хранится только разбор.** Регулярки по формату `scripts/ci_job_resources.py` santinel; поля неизвестного формата пустые, `parsed=0`. Сырые логи могут содержать переменные окружения, поэтому на диск не пишутся.
3. **Источник пайплайна в replay.** Цепочка «следующий пайплайн на ветке» строится только по push и `merge_request_event`; расписания, API и веб из неё исключены.
4. **Трассируемость через id.** Документы ссылаются на показатель по id в обратных кавычках; `check` ищет такие id с известными префиксами разделов. Таблица цифр для слайдов генерируется, не пишется руками.

## Risks / Trade-offs

- Формат `job-resources:` принадлежит другому проекту и может поменяться: разбор упадёт в `parsed=0`, отчёт покажет «нет данных», но не соврёт.
- `check` проверяет существование id, а не значение числа рядом с ним. Сверка значений — через `numbers.md`.
