# E08. Сколько тестов нужно на изменение агента: история santinel

Дата: 10.11.2026. Гипотезы H4 (прогон по дельте) и H10 (полный набор — один раз на ветку). Метод: статический анализ истории git, тесты не запускались. Копия `raft-estimate/santinel` (только чтение, push отключён), ветка `main` с 11.10.2026: 367 влитых изменений, 1 817 отдельных коммитов.

Воспроизвести:

```
python -m runners affected --repo <клон santinel> --since 2026-10-11 \
  --weights infra/ci/pytest-file-durations.json --weights infra/ci/dbt-file-durations.json \
  --invalidate "pyproject.toml" --invalidate "requirements*.txt" --invalidate "uv.lock" --invalidate "setup.cfg" \
  --invalidate "pytest.ini" --invalidate "alembic.ini" --invalidate "docker-compose.test.yml" --invalidate "migrations/*" \
  --suite "tests/dbt/=dbt/*" [--per-commit]
```

Пути `--weights` — относительно клона. Правила — в `runners/affected.py`, тесты правил — `tests/test_affected.py`.

## Правила

Для каждого изменения затронутые файлы тестов определяются теми же правилами, что у кэша рантайма (ADR-0005), с консервативными дополнениями:

- изменились lock-файлы, конфиг тестов или миграции — затронуты все тесты;
- изменилось что-то в `dbt/` — затронуты все тесты `tests/dbt/`;
- изменился не-Python файл в `tests/` — затронуты тесты того же каталога и ниже;
- изменился не-Python файл вне `tests/` — затронуты Python-модули, в тексте которых упомянуты его путь, имя или каталог, а через них — тесты по обратному замыканию импортов;
- изменился `.py` — затронуты тесты, в замыкании импортов или цепочке `conftest.py` которых он есть.

Доля времени взвешивается по замеренным секундам файлов тестов из CI самого santinel (995 файлов, 44 239 с).

## Результат

| Разрез | Изменений | Нужно тестового времени: медиана | среднее | p90 | Полный прогон по правилам | Тесты не нужны |
|---|---|---|---|---|---|---|
| Влитое изменение (MR) | 367 | 62,8% | 63,5% | 99,6% | 27,2% | 3,0% |
| Отдельный коммит агента | 1 817 | 51,2% | **45,5%** | 98,6% | 15,5% | 11,0% |

С грубым правилом «любой не-Python файл вне `tests/` — все тесты» получалось 64,9% и 48,4%, а полный прогон требовался в 81,7% и 52,6% случаев. Почти все такие файлы — документы, ADR и terraform, которых тесты не упоминают.

## Почему не меньше

Корневой `tests/conftest.py` через импорты достаёт **514 из 521 модуля `app/`**. По замыканию импортов любое изменение кода приложения затрагивает почти весь набор. Экономию дают коммиты, которые меняют только тесты, документы, SQL-модели dbt и подобное, а таких у агентов много: 11% коммитов не требуют тестов вовсе.

## Выводы

1. **H4 по импортам экономит в среднем 54% тестового времени на коммит агента** (нужно 45,5%) и 36% на влитое изменение. Это уже умеет кэш рантайма.
2. **Дальше точность упирается в связность через `conftest.py`.** Следующая ступень — выбор по покрытию (`pytest-testmon`, ночная карта TIA, которая у santinel уже есть). Проектам стоит держать корневой `conftest.py` лёгким: импорты внутри фикстур, а не на уровне модуля.
3. **H10** подтверждается с другой стороны: на одно влитое изменение приходится в среднем 5 коммитов (1 817 / 367), и каждый сейчас может запускать полный набор, хотя нужно ему в среднем меньше половины.

## Ограничения

- Анализ статический: динамические импорты и чтение файлов по вычисленным путям не видны. Правило по каталогу смягчает это с запасом.
- `main` — история влитых изменений. Отдельные пуши агента в ветки MR после слияния не сохраняются; коммиты — их приближение.
