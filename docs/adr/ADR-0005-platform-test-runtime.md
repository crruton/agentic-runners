# ADR-0005: Раннеры разгружаем тестовым рантаймом платформы, а не размером раннеров

- Статус: APPROVED (решение владельца, 10.11.2026)
- Дата: 10.11.2026
- Applies To: `runtime/**`, `docs/experiments/E04-*`
- Supersedes: нет

## Контекст

21 раннер забит агентной разработкой. E03 показал, что размер раннера — слабый рычаг: больше памяти не ускоряет, крупнее раннер снижает пропускную способность. Нагрузку создают три вещи:

- повторные прогоны одних и тех же тестов на неизменном коде (131 пайплайн в сутки в одном проекте);
- холодный старт каждого задания и каждого воркера: каждый xdist-воркер заново импортирует код и занимает 0,8–1,5 GiB, отсюда OOM в cgroup;
- общая очередь без разделения тяжёлого и лёгкого.

Репозитории проектов менять нельзя (ADR-0002). Права на конфиг раннеров появятся позже. Общего хранилища (MinIO) под кэш не будет — только локально.

## Решение

Тестовый рантайм платформы — pytest-плагин `agentic_runtime`, который подключается снаружи проекта (`-p agentic_runtime` через `PYTEST_ADDOPTS` в конфиге раннера или в харнесе агента):

1. **Воркеры форком от прогретого процесса.** Сбор тестов и импорты выполняются один раз, затем `gc.freeze()` и `fork()`. Страницы импортированного кода остаются общими (copy-on-write), cgroup учитывает их один раз. Упавший воркер перезапускается дешёвым форком, а не новым интерпретатором. Переменные `PYTEST_XDIST_WORKER*` совместимы с xdist, чтобы фикстуры проектов (БД на воркер) работали без изменений.
2. **Кэш результатов по хэшу входов.** Ключ файла теста — хэш его содержимого, локального замыкания импортов, conftest-файлов, lock-файлов и версии Python. Если файл уже проходил с тем же ключом, его тесты не запускаются. Хранилище — локальный каталог (на хосте раннера или у агента).
3. **Телеметрия задания.** Строки `job-resources:` в формате santinel (cgroup v2, `/proc/vmstat`, PSI) для любого проекта — данные для снимка без Grafana (ADR-0003).

## Последствия

- Эффект достигается без правок в репозиториях и без закупки железа.
- Форк требует Linux; на других ОС плагин работает последовательно и предупреждает.
- Кэш по статическому замыканию импортов не видит динамические импорты и внешнее состояние (схема БД, данные). Поэтому есть явное отключение, дополнительные glob-входы и правило: кэшем для проверки перед слиянием наполняет только CI.

## Reconsider When

- Доля тестов, пропущенных по кэшу и упавших потом в полном прогоне, больше 0,1%.
- Проекты массово переходят на другой раннер тестов (не pytest).
- Появляется общее хранилище раннеров: тогда кэш становится общим для парка.
