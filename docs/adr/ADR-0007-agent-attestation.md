# ADR-0007: CI принимает подписанное свидетельство агента вместо повторной проверки

- Статус: APPROVED (запрос владельца 11.11.2026: решение, снижающее проблему практически до нуля)
- Дата: 11.11.2026
- Applies To: `runtime/agentic_runtime/attest.py`, `ci-templates/agentic-attest.yml`, `skills/ci-preflight/**`
- Supersedes: нет. Дополняет ADR-0006: проверка до пуша (H2) становится последней проверкой, а не первой из двух.

## Контекст

Общий CI повторяет проверки, которые агент может выполнить и уже выполняет у себя: 96% падений воспроизводятся локально (E05). Машина агента большую часть времени ждёт ответа модели, её процессор простаивает. Проверки в MR-пайплайнах и на ветках — 66,9% часов раннеров (E10). santinel уже пропускает тесты на `main` по sha, проверенному поездом слияния (`ci:already-tested`): доверие к прошлой проверке того же дерева работает внутри CI.

## Решение

- Агент выполняет каждую проверку проекта на закоммиченном дереве (`attest run -- <команда>`) и при успехе записывает свидетельство в git note `refs/notes/agentic-attest`: дерево, команда, отпечаток окружения (Python, ОС, архитектура, lock-файлы дерева, строка `AGENTIC_ATTEST_ENV`), подпись HMAC-SHA256. Свидетельство пушится вместе с веткой.
- В CI одно задание-шлюз на пайплайн проверяет свидетельства по списку проверок проекта. Принятые проверки в дочерний пайплайн не попадают. Нет свидетельства, не совпали дерево или окружение, недействительна подпись — проверка запускается как обычно.
- **Аудит:** детерминированная доля коммитов (по умолчанию 10%) проверяется полностью даже при действительном свидетельстве. Расхождение («свидетельство говорило успех, проверка упала») печатается явно и служит основанием отозвать ключ.
- Перед готовностью MR агент перебазируется на целевую ветку и аттестует итоговое дерево, чтобы поезд слияния тоже принимал свидетельство.

## Последствия

- По истории: с раннеров уходит 74,5% часов при шлюзе на пайплайн и 79,1–83,6% вместе с поездом слияния (E10). На раннерах остаются сборки, выкатка, расписания и аудит.
- **Модель доверия.** Подпись HMAC с общим ключом доказывает, что свидетельство выдал держатель ключа, а не что проверка выполнялась. Честность держит аудит: подделка обнаруживается с вероятностью доли аудита на каждом коммите. Ключ — CI-переменная (masked) и секрет на машинах агентов; ротация — сменой переменной.
- Нестабильные (flaky) тесты и расхождение окружений проявятся как расхождения аудита: их нужно разбирать, а не игнорировать.
- Сборки и выкатка остаются в CI: артефакты для выкатки собираются только в доверенной среде.

## Reconsider When

- Доля расхождений аудита выше 1% коммитов за неделю.
- Появляется доверенная изоляция на машинах агентов (аттестуемая песочница) — тогда HMAC заменяется на подпись среды выполнения.
- Окружение агентов систематически не совпадает с CI (доля проверок «окружение не совпадает» выше 20%) — тогда агенты выполняют проверки в образе CI.
