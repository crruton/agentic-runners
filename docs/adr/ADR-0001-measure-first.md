# ADR-0001: Сначала замер, затем одно изменение за раз

- Статус: APPROVED
- Дата: 09.11.2026
- Applies To: `collect/**`, `bench/**`, `docs/experiments/**`
- Supersedes: нет

## Контекст

Результаты пойдут в публичный доклад. Девять раннеров перегружены, и изменения влияют друг на друга.

## Решение

- Любое изменение вводим только после записанной базовой линии.
- Меняем одну вещь за раз на 1–2 раннерах; остальные служат контрольной группой.
- Каждый эксперимент записываем в `docs/experiments/EXX-*.md`: гипотеза, условия, метрики, результат.
- В доклад попадают только числа из журнала экспериментов.

## Последствия

Работа идёт медленнее, чем при одновременном внедрении всего. Зато вклад каждого изменения доказуем.

## Reconsider When

- Пиковая перегрузка блокирует разработку сильнее, чем на 1 рабочий день. Тогда допустим пакетный выкат с оценкой по истории.
