# ADR-0002: Изменения пайплайнов оцениваем повторным прогоном истории, а не правками в репозиториях

- Статус: APPROVED (решение владельца, 09.11.2026)
- Дата: 09.11.2026
- Applies To: `runners/whatif.py`, `docs/experiments/**`
- Supersedes: нет

## Контекст

Согласия владельцев проектов на правку `.gitlab-ci.yml` нет. Тем не менее нужно оценить политики пайплайнов (`interruptible`, автоотмена), а для ADR-0001 нужен доказуемый эффект каждого изменения.

## Решение

- Репозитории проектов только читаем, через GitLab API.
- Эффект политики пайплайна считаем повторным прогоном (replay) истории заданий из снимка: прямой расчёт освобождённого времени плюс модель очереди с калибровкой по фактическому p95.
- Цепочку вытеснения строим с учётом источника пайплайна (push, MR). Пайплайны по расписанию, из API и из веб-интерфейса в ней не участвуют.

## Последствия

- Оценка не требует ничьего согласия и воспроизводится офлайн.
- Это модель, а не замер: обратную связь (агент пушит чаще, когда CI быстрее) она не учитывает. В докладе подаётся как оценка.

## Reconsider When

- Владелец проекта даёт согласие на пробное изменение конфига CI. Тогда подтверждаем replay живым A/B.
- Расхождение replay и факта больше 30% на любом подтверждённом изменении.
