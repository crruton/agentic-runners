## Как это читать

- На одном ноутбуке несколько регистраций (`notebook-runner-5`, `notebook-runner-5-2`). Значит, 22 регистрации — это меньше 22 машин.
- Теги `cpu-N`/`ram-Ng` при хостах на 8–16 ядер похожи на **лимиты на задание** в Docker executor (`cpus`, `memory` в `config.toml`), а не на размер машины. Это гипотеза. Если она верна, то тяжёлые шарды тестов (pytest, dbt) работают в контейнере на 2–4 CPU и 3–4 ГБ, при том что у хоста есть свободные ядра. Тогда давление нужно смотреть внутри cgroup задания (`cpu.stat` throttling, `memory.events` high/max), а не на уровне хоста.

## Открытые вопросы

1. `config.toml` каждого хоста: `concurrent`, `limit`, `[runners.docker] cpus/memory/memory_swap`, executor.
2. Модели CPU, объём RAM и тип диска по хостам.
3. Даты регистрации раннеров (GitLab API `/runners/:id` с правами администратора), чтобы подтвердить «4 → 22» данными.
4. Ядро, дистрибутив, cgroup v1 или v2 на хостах.
