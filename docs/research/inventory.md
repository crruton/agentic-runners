## Как это читать

- На одном ноутбуке несколько регистраций (`notebook-runner-5`, `notebook-runner-5-2`). Значит, 22 регистрации — это меньше 22 машин.
- **Подтверждено логами** (`job_resources`, `docs/research/santinel-ci.md`): Docker executor, cgroup v2, заданию выдаётся cpuset на 4 CPU (на `nvme-runner` — 2) и `memory.max` 4096–8192 MiB. Теги `cpu-N`/`ram-Ng` — это лимиты на задание, а не размер машины. Тяжёлые шарды тестов (pytest, dbt) работают в контейнере на 4 CPU и 4–8 GiB при 8–12 свободных ядрах хоста. Давление смотрим внутри cgroup задания (`memory.events`, `memory.peak`) и на хосте (`/proc/vmstat oom_kill`, PSI) — E02.

## Открытые вопросы

1. `config.toml` каждого хоста (недоступен): `concurrent`, `limit`, `pull_policy`. Лимиты на задание уже известны из логов.
2. Тип диска по хостам; модели CPU есть в логах у 41% заданий (`cpu_model` в `job_resources`).
3. Даты регистрации раннеров (GitLab API `/runners/:id` с правами администратора), чтобы подтвердить «4 → 22» данными.
4. Ядро и дистрибутив хостов (cgroup v2 подтверждён логами).
